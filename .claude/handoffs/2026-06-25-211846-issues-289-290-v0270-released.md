## Codebase Understanding

## Architecture Overview

`agent-tmux` is the single engine; `claude-tmux`/`codex-tmux`/`agy-tmux` are one-line `exec agent-tmux <cli>` shims — so a change in `agent-tmux` covers ALL engines. Per-agent state lives at `$TMUX_AGENT_DIR/<name>/` keyed by **bare session name** (engine-independent); tmux session names are `<prefix>-<name>` where prefix is per-engine (`claude-cli`/`codex-cli`/`agy-cli`) via `session_for_name()`. This split is the crux of #290.

## Deferred Items (intentionally out of scope — candidates for new issues)

- **Cross-engine `exited` liveness**: `agent-tmux <cli> watch` checks tmux `has-session` with the invoking cli's prefix, so a still-running foreign-engine session reads as a false `exited`. True fix = resolve each watched name's owning wrapper for the liveness check (e.g. via tmux-agent-sessions resolution). Documented as a caveat in v0.27.0; not fixed.
- **Generic `<cli>-cli-` prefix support in tmux-agent-sessions**: only claude/codex/agy/dialogue are recognized; arbitrary custom CLIs are not inventoried.

## Potential Gotchas

- zsh (not bash) does NOT word-split unquoted `$var` — bit me in a `for ... set -- $w` loop; iterate explicitly.
- ctx_execute's shell rejected a `for` loop (parse error) — used Bash directly for short fixed-output env probes.
- Bash tool hard-caps at 10 min; `watch --timeout` >600s gets truncated by the harness, not the worker. Use bounded waits ≤540s and re-poll.
- Wrappers are NOT on PATH here; invoke via bundle path `skills/tmux-agent-tools/scripts/<wrapper>`.
- agy (Antigravity/Gemini-Flash) TUI is slow; initial `start` prompt may not submit — verify with capture and resend via `send` with a higher `AGY_TMUX_SUBMIT_DELAY` (used 0.8).
