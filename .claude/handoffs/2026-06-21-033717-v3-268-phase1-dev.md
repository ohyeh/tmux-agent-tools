### Key Patterns Discovered

- **Session identity evidence lives on disk, not in `--help`.** To judge whether a CLI's session id is
  capturable, inspect its store dir (`~/.claude/projects/`, `~/.codex/sessions/`, `~/.gemini/antigravity-cli/`),
  not just help text. `--help` only tells you resume EXISTS, not where the id lives or how to correlate it.
- Profile keys are mechanism-only; do NOT infer capability from `heuristic_family` (e.g. agy/cursor/grok
  share `heuristic_family=codex` but that is not transcript-source proof).
- New session-id writes must be SINGLE-WRITER (mutual exclusion), not lock-based.

## Context for Resuming Agent

## Important Context

The design is FROZEN in `.workflow/v3-structured-session-id/design-proposal.md` (incl. the round-3 "agy source
FOUND" addendum) — treat it as the impl spec. The per-CLI split is asymmetric BY DESIGN: claude SUPPLIES its
id (`--session-id`, race-free, sidecar written synchronously pre-launch, NO background capture / NO pane
fallback / NO transcript scan); codex and agy must CORRELATE a CLI-owned store after start (newest-new file
within a bounded window, validated by id/cwd equality), bailing to an OBSERVABLE null on ambiguity. The two
mechanisms (`supplied`, `transcript`) cover three proven CLIs (claude / codex / agy). Everything default-off
until the L gate. v3 and #268 SHARE Phase 1 (one profile-key round) but their outputs stay decoupled:
`result.json` belongs to #268, `session-meta.json` belongs to v3.

### Assumptions Made

- `claude --session-id <uuid>` sets the resumable id (verified via --help; resume-id equality assumed, no counterexample found).
- agy `--conversation <uuid>` resumes the conversation whose UUID names `conversations/<uuid>.db` (verified file naming + cwd map; live resume not yet run).
- jq remains the only dependency; atomic tmp→mv sidecar write preserved.

### Potential Gotchas

- Do NOT add session-id to result.json — it lives only in session-meta.json (security: it's a resume capability).
- Do NOT spawn BOTH pane capture and structured capture — that reintroduces the two-writer TOCTOU race. Mutual exclusion only.
- agy `last_conversations.json` is in `cache/` — may be stale; cross-check `conversations/<uuid>.db` mtime ≥ launch.
- Bundled `agy.conf` stays interactive/off; oneshot + capture are user-local opt-in until live-verified.
- Phase 1 must NOT change runtime behavior — it only adds parsed keys with safe defaults.
