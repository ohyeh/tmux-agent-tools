# v0.3.0 Roadmap

`v0.2.0` made tmux-agent-tools a bounded orchestration package: wrappers, dialogue transcripts, pair-review, remote participants, explicit GitHub comment helpers, and reviewed release automation are now in place. `v0.3.0` should improve long-running use rather than add more autonomy.

## Direction

The next public layer is session hygiene and transcript usability:

```text
installable wrappers
  -> bounded orchestration
  -> understandable sessions and durable transcripts
  -> safer sharing and release evidence
```

## P0: Session Hygiene

Make active and stale tmux-agent sessions easier to reason about without destructive defaults.

Candidate work:

- cross-wrapper inventory command that shows Claude/Codex owned sessions together;
- consistent stale/exited/running labels derived from wrapper `status`;
- safe cleanup preview for tool-owned sessions;
- explicit cleanup execution flag for bulk stop operations;
- no cleanup outside the wrapper-owned tmux prefixes.

Status: merged in PR #18 (`32135e0`). The first slice adds `tmux-agent-sessions list [--json]` and `cleanup --preview/--execute`, keeps preview read-only, requires an explicit filter or `--all` for execution, and limits cleanup to known tmux-agent-tools prefixes.

Acceptance criteria:

- default inventory is read-only;
- cleanup preview lists exactly which sessions would be stopped;
- execution mode only stops sessions owned by `claude-tmux`, `codex-tmux`, or `tmux-agent-dialogue`;
- JSON output is available for automation;
- CI covers fake or wrapper self-test sessions without starting real Codex/Claude agents.

## P0: Transcript Schema And Validation

Treat dialogue JSONL as a public artifact.

Candidate work:

- document transcript event types and required fields;
- add `tmux-agent-dialogue validate-transcript --transcript <path>`;
- validate `turn` and `failure` events separately;
- keep validation local-only with no tmux or GitHub dependency;
- use the validator in CI for fake dialogue, pair-review, summary, and GitHub comment helper checks.

Status: merged in PR #19 (`8c3607a`). The first slice validates required `turn`/`failure` JSONL fields and wires validation into summary and GitHub comment rendering.

Acceptance criteria:

- invalid JSONL fails with line-level diagnostics;
- missing required fields fail clearly;
- existing fake dialogue and pair-review transcripts validate;
- summary and GitHub comment helpers reject invalid transcripts before rendering.

## P0: Failure Classification

Turn failures should explain what likely happened, not only that a marker timed out.

Candidate work:

- classify marker timeout, session missing, CLI exited, SSH prompt, and permission/first-run prompt where detectable;
- include `failure_type` in failure JSONL events;
- preserve pane tail for diagnosis;
- keep classifications conservative and evidence-based.

Status: merged in PR #20 (`8ca4aeb`). The first slice classifies credential-free fake failures as `marker_timeout` or `session_missing`, validates known `failure_type` values, and keeps text-pattern classifications conservative.

Acceptance criteria:

- timeout failure events include `failure_type`;
- existing timeout behavior remains backward-compatible;
- tests cover at least marker timeout and missing session paths with fake participants or wrapper-level fixtures.

## P1: Safer Transcript Sharing

GitHub comment and summary helpers should make accidental oversharing harder.

Candidate work:

- `--max-lines` and `--max-bytes` limits for rendered summaries;
- optional `--redact-pattern <regex>` that can be repeated;
- visible truncation/redaction notes in generated Markdown;
- defaults that preserve current local behavior unless a sharing command is used.

Status: merged in PR #21 (`132289f`). The first slice added sharing-only `--max-lines`, `--max-bytes`, and repeated `--redact-pattern` support to `summarize` and `github-comment`.

Acceptance criteria:

- redaction applies before GitHub comment posting;
- dry-run output shows the same body that would be posted;
- no external posting occurs without `--post-github-comment`.

## P1: Stable Status JSON

Make `status --json` a documented contract for wrappers and higher-level tools.

Before adding richer capture fields, refactor JSON construction to use `jq` or another structured JSON writer instead of hand-built `printf` output. Captured pane text can contain quotes, newlines, and control characters.

Candidate fields:

- `tool`;
- `session`;
- `exists`;
- `running`;
- `exit_detected`;
- `confirmation_detected`;
- `local_or_remote`;
- `last_capture_lines`.

Acceptance criteria:

- `claude-tmux status --json` and `codex-tmux status --json` share the same stable field names;
- docs show which fields are best-effort diagnostics;
- wrapper JSON output is constructed through a structured JSON writer;
- CI validates JSON shape with `jq`.

Status: merged in PR #22. The first slice aligns wrapper fields, uses `jq` for JSON construction, documents stable versus diagnostic fields, and adds CI shape checks for missing, running, and exit-detected sessions.

## P2: Participant Profiles

Reusable participant profiles can reduce CLI flag repetition without making the public package personal.

Candidate work:

- optional config file under `~/.config/tmux-agent-tools/participants.json`;
- profile fields for `agent`, `ssh`, and `workdir`;
- command-line flags override profile values;
- docs use generic host and path examples only.

Status: merged in PR #23 with follow-up docs in PR #24. The first slice adds `--agent-a-profile`, `--agent-b-profile`, and `--participants-config` to `tmux-agent-dialogue`, with top-level JSON profiles and existing participant validation rules.

Non-goal for v0.3: project-specific host shortcuts.

## P2: More Thin Presets

Additional presets can be useful only if they stay thin wrappers over `tmux-agent-dialogue`.

Candidates:

- `debate`;
- `critic`;
- `handoff`.

Status: merged in PR #25, with coverage/docs follow-ups in PR #26, PR #27, and PR #28. The first thin preset slice adds `critic` as a four-turn bounded critique/response loop over the existing dialogue runner, with positive even `--turns` validation and no external side effects. Generic transcript summary and GitHub comment rendering now use the `transcript` label unless a preset explicitly sets its own label.

Non-goal for v0.3: hidden GitHub posting, merging, scheduling, or unbounded loops.

## Non-Goals

- personal OpenClaw, Mac mini, or project-specific shortcuts;
- autonomous unbounded loops;
- default real Codex/Claude runs in CI;
- default GitHub posting or PR mutation;
- destructive cleanup outside wrapper-owned tmux sessions;
- secret or token management beyond dependency diagnostics.

## Verification Plan

Minimum checks for v0.3 branches:

- shell syntax checks for all wrapper scripts and `tmux-agent-dialogue`;
- shellcheck linting for wrapper scripts, workflow shell blocks where practical, and `tmux-agent-dialogue`;
- wrapper self-tests;
- transcript validator checks against fake dialogue and pair-review transcripts;
- `jq` shape checks for JSON status and transcript artifacts;
- credential-free CI only;
- real-agent tests remain manual release evidence.

## Remaining v0.3 Candidate Work

The main v0.3 slices have landed. Remaining work should be release-hardening rather than new autonomy:

- refresh README and roadmap wording for the merged v0.3 surface;
- normalize tmux pane capture so soft-wrapped screen lines do not distort markers, transcripts, or summaries;
- keep copy-mode usable for normal keyboard/mouse users even when a platform clipboard helper such as `pbcopy` is unavailable, with copy bindings for keyboard and mouse drag release plus an explicit `*_TMUX_CLIPBOARD=internal` escape hatch for terminal-specific clipboard behavior;
- run one manual real Codex/Claude smoke for wrappers and one bounded dialogue before release;
- prepare a `v0.3.0` release PR with CHANGELOG notes and stable Formula bump after the release workflow creates the tag.
