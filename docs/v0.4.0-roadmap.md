# v0.4.0 Roadmap

`v0.3.0` made tmux-agent-tools a stable session hygiene and transcript usability package: stable Homebrew installs now include `claude-tmux`, `codex-tmux`, `tmux-agent-dialogue`, and `tmux-agent-sessions`; release automation is reviewed; transcript validation and safer sharing are in place.

`v0.4.0` should make the tools more automation-ready without expanding into hidden autonomy. The main theme is: more accurate state, better handoff primitives, and easier local sharing pipelines.

Status: core automation-readiness slices have landed on `main`; release notes, hardened workflow dry-run evidence, and release-process docs are current. Publishing `v0.4.0` still requires an explicit operator go/no-go decision, followed by the post-release Formula bump PR.

## Objective

Make tmux-agent-tools easier to use as a reliable automation substrate:

- wrappers expose enough state for higher-level tools to decide whether a session is ready, blocked, exited, or still running;
- session inventory agrees with wrapper status rather than assuming every owned tmux session is running;
- dialogue presets cover common bounded handoff flows without posting, merging, scheduling, or looping indefinitely;
- transcript summaries and GitHub comment bodies can be prepared through explicit local files.

## P0: Status And Session Truth

Current signals:

- `claude-tmux status --json` and `codex-tmux status --json` expose stable shared fields.
- `tmux-agent-sessions list --json` now reuses wrapper status fields for Claude/Codex rows and adds a derived `state`.
- `README.md` documents the shared wrapper status contract, including best-effort `diagnostic`, `confirmation_detected`, and `blocked_reason` fields for both Claude and Codex.

Candidate work:

- Keep `tmux-agent-sessions cleanup --preview` read-only, but include enough state to decide whether cleanup is safe - implemented.
- Add bounded readiness diagnostics when the pane appears to be waiting for approval, permission, SSH, login, or has exited - implemented.
- Avoid exact diagnostic-string contracts; make the boolean or enum-like fields stable, and keep human text best effort - implemented.

Exit criteria:

- fake tmux sessions can demonstrate `running` and exited-but-capturable states - implemented;
- `tmux-agent-sessions list --json` has `jq` assertions for state shape - implemented;
- cleanup behavior remains opt-in and scoped to known prefixes - implemented.

## P1: Status Contract Expansion

Current `status --json` fields are intentionally small. v0.4 can add fields that help orchestration without making callers parse pane text:

- `last_capture_lines`: small tail window for human diagnosis, bounded by a fixed default - implemented;
- `confirmation_detected`: boolean for known first-run, approval, or permission prompts - implemented;
- `blocked_reason`: nullable enum-like value such as `permission_prompt`, `approval_prompt`, `ssh_prompt`, `login_prompt`, or `cli_exited` - implemented;

Constraints:

- Do not make long pane capture part of default status output.
- Do not treat diagnostics as proof of root cause.
- Do not auto-accept any prompt.

Verification:

- `claude-tmux status --json` and `codex-tmux status --json` both validate with `jq`.
- Existing stable fields keep their names and types.
- New fields are documented as stable or diagnostic.

## P1: Handoff Preset

Add a thin `handoff` preset to `tmux-agent-dialogue` for bounded context transfer:

```bash
tmux-agent-dialogue handoff \
  --workdir . \
  --prompt-file task.md \
  --transcript handoff.jsonl \
  --agent-a codex \
  --agent-b claude
```

Shape:

- Agent A produces a concise context handoff.
- Agent B responds with readiness, risks, and next-action summary.
- The preset writes only local transcript and optional summary files.

Non-goals:

- no automatic task execution after handoff;
- no GitHub posting unless the existing explicit `github-comment --post-github-comment` path is used;
- no scheduler or daemon mode.

Verification:

- fake two-turn handoff transcript passes `validate-transcript` - implemented;
- non-default turn counts are rejected unless the implementation explicitly defines a multi-step handoff flow - implemented;
- cleanup behavior matches existing dialogue guarantees.

## P1: Summary File Pipeline

`summarize` can write a summary file, and `github-comment` can render a dry-run body from a transcript. v0.4 should close the local artifact pipeline:

- allow `github-comment --summary-file <path>` to reuse a pre-rendered summary body - first slice implemented;
- keep `--post-github-comment` explicit and opt-in;
- keep `--max-lines`, `--max-bytes`, and repeated `--redact-pattern` behavior visible in the rendered Markdown.

Verification:

- summarize-to-file then github-comment-from-file produces the same body shape;
- invalid transcript input still fails before rendering when transcript mode is used;
- `--summary-file` with `--post-github-comment` remains explicit.

## P2: Operator Ergonomics

Useful but not release-blocking:

- environment override for default capture tail size;
- optional `pair-review --swap` for agent order - implemented;
- participant profile `env` support for generic per-session environment variables - implemented;
- more visible docs around human tmux copy/mouse UX follow-ups.

These should stay generic. Do not encode personal hostnames, project directories, or private workflow shortcuts.

## Non-Goals

- multi-agent fan-out or fan-in orchestration;
- unbounded watch loops;
- CI that runs real Claude or Codex credentials;
- automatic release publishing from local shell;
- hidden GitHub posting, merging, scheduling, or cleanup;
- personal OpenClaw, Mac mini, or dotfiles shortcuts in public core.

## Minimum Checks For v0.4 Branches

- `zsh -n` for every changed script;
- skill quick validation;
- `ruby -c` and `brew style` for Formula changes;
- targeted fake tmux smoke tests for changed wrapper/session behavior;
- `jq` shape checks for JSON outputs;
- fake dialogue transcript validation for preset changes;
- real Claude/Codex smoke only as manual release evidence, not default CI.

## First Candidate Slice

Start with `tmux-agent-sessions` state accuracy because it is small, measurable, and underpins every higher-level automation surface:

- add wrapper-backed state collection for known Claude/Codex sessions;
- preserve existing read-only list and preview behavior;
- test running and exited-but-capturable states with fake tmux sessions;
- document the state contract before adding larger presets.
