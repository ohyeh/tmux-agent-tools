# v0.5.0 Roadmap

The `v0.4.0` work on `main` made tmux-agent-tools more automation-ready: shared wrapper status fields, session inventory state, bounded diagnostics, handoff, summary-file comment input, pair-review swap, participant profile env, and hardened release validation are in place. Publishing the actual `v0.4.0` tag still requires explicit operator approval.

`v0.5.0` should improve observability and multi-session composability without expanding into hidden autonomy. The theme is: bounded monitoring, richer machine contracts, and local artifacts that help operators decide what to do next.

Status: planning. No `v0.5.0` tag, release, or Formula bump exists. `v0.4.0` still requires an explicit operator go/no-go decision before publishing.

## Objective

Make tmux-agent-tools easier to supervise from shell scripts and higher-level tools:

- session inventory can be sampled over a bounded window without creating an unbounded daemon;
- wrappers expose enough machine-readable exit details for operators to distinguish normal completion from failure;
- transcript and summary tools can pin or emit contract versions for predictable CI checks;
- local trigger artifacts can signal blocked sessions without accepting prompts or posting externally.

## P0: Bounded Session Watch

Add a bounded watch mode to `tmux-agent-sessions list`:

```bash
tmux-agent-sessions list --watch --json --count 5 --interval 3
```

Shape:

- reuse the existing `list --json` inventory collector;
- emit one JSON snapshot per poll;
- stop after `--count N`;
- keep `--count 0` as an immediate no-op success;
- reject unbounded watch mode unless a future implementation defines an explicit safe contract.

Verification:

- fake tmux sessions can run `--watch --json --count 2 --interval 1`;
- `jq` can validate two emitted snapshots and the existing row schema;
- `--count 0` exits without polling;
- no external credentials, real Claude/Codex calls, GitHub writes, scheduling, or release actions.

## P0: Exit Detail Contract

Extend wrapper `status --json` with minimal exit detail:

- `exit_code`: integer or null, parsed from wrapper exit-code markers;
- preserve `running`, `exit_detected`, `blocked_reason`, and `diagnostic` semantics;
- treat exit details as machine-readable evidence, not root-cause diagnosis.

Rationale:

- `blocked_reason: cli_exited` currently tells callers that the CLI ended, but not whether it ended cleanly;
- operators need a stable field before deciding whether to restart, inspect, or ignore a session.

Verification:

- fake local and remote exit markers produce expected `exit_code`;
- missing/running sessions report `exit_code == null`;
- existing stable status fields keep their names and types.

Implementation note: the intended source is the existing pane footer markers, such as `local command exited with code <n>` and `remote command exited with code <n>`. Do not infer exit codes from arbitrary model output.

## P1: Transcript Contract Versioning

Add explicit schema-version validation:

```bash
tmux-agent-dialogue validate-transcript --schema-version 1 --transcript transcript.jsonl
```

Constraints:

- keep the current transcript shape valid as the initial version;
- treat the current default validator behavior as schema version `1`;
- reject unsupported schema versions with a clear error;
- do not silently upgrade or rewrite transcripts.

Verification:

- current fake dialogue transcripts validate with the default and explicit schema version;
- unsupported versions fail before reading external systems.

## P1: Local Blocked Trigger Artifacts

Allow bounded dialogue runs to write a local trigger file when a participant becomes blocked:

```bash
tmux-agent-dialogue pair-review \
  --on-blocked-trigger blocked.json \
  --transcript review.jsonl
```

Constraints:

- write only local files requested by flags;
- never auto-accept permission, approval, SSH, or login prompts;
- no GitHub posting unless the existing explicit comment command is used.

Verification:

- fake status with `blocked_reason` writes the trigger artifact;
- non-blocked runs do not write it;
- trigger JSON includes participant name, `blocked_reason`, and timestamp.

## P1: Summary Output Formats

Add structured summary output for scripts:

```bash
tmux-agent-dialogue summarize --transcript review.jsonl --output-format json
```

Shape:

- keep Markdown as the default human-facing format;
- add JSON for machine consumption;
- include redaction metadata and truncation indicators.

Verification:

- Markdown output remains unchanged by default;
- JSON output validates with `jq`;
- redaction and truncation behavior remains visible.

## P2: Operator Ergonomics

Useful but not release-blocking:

- stronger coverage for `tmux-agent-sessions cleanup --preview --json` scriptable cleanup decisions;
- participant profile per-agent timeout overrides;
- `github-comment --edit-existing` to update a known marker comment instead of appending;
- coverage for empty `--summary-file` and `--max-bytes` summary-file behavior.

## Non-Goals

- real Claude/Codex credentials in CI;
- unbounded watch loops or daemon mode;
- fan-out or fan-in multi-agent orchestration;
- hidden prompt acceptance, GitHub posting, merging, scheduling, cleanup, tag creation, or release publishing;
- personal OpenClaw, Mac mini, hostnames, dotfiles, or private workflow shortcuts in public core;
- status fields that claim authoritative root cause beyond bounded pane evidence.

## First Candidate Slice

Start with bounded session watch because it is small, measurable, credential-free, and unlocks later blocked-session triggers:

- add `tmux-agent-sessions list --watch --json --count N --interval S`;
- require a finite `--count`;
- test two JSON snapshots with `jq`;
- test `--count 0` as an immediate success;
- document that watch mode is bounded polling, not a scheduler or daemon.
