# v0.5.0 Roadmap

The `v0.4.0` work on `main` made tmux-agent-tools more automation-ready: shared wrapper status fields, session inventory state, bounded diagnostics, handoff, summary-file comment input, pair-review swap, participant profile env, and hardened release validation are in place. Publishing any release tag still requires explicit operator approval through the reviewed Release workflow.

`v0.5.0` should improve observability and multi-session composability without expanding into hidden autonomy. The theme is: bounded monitoring, richer machine contracts, and local artifacts that help operators decide what to do next.

Status: all planned `v0.5.0` P0/P1/P2 slices have landed on `main`, and the Release workflow dry-run for `v0.5.0` passed. No `v0.5.0` tag, GitHub Release, or Formula bump exists. The next release action is an explicit operator go/no-go for the non-dry-run Release workflow.

## Objective

Make tmux-agent-tools easier to supervise from shell scripts and higher-level tools:

- session inventory can be sampled over a bounded window without creating an unbounded daemon;
- wrappers expose enough machine-readable exit details for operators to distinguish normal completion from failure;
- transcript and summary tools can pin or emit contract versions for predictable CI checks;
- local trigger artifacts can signal blocked sessions without accepting prompts or posting externally.

## P0: Bounded Session Watch

Add a bounded watch mode to `tmux-agent-sessions list` - first slice implemented:

```bash
tmux-agent-sessions list --watch --json --count 5 --interval 3
```

Shape:

- reuse the existing `list --json` inventory collector - implemented;
- emit one JSON array snapshot per poll - implemented;
- stop after `--count N` - implemented;
- keep `--count 0` as an immediate no-op success - implemented;
- reject unbounded watch mode unless a future implementation defines an explicit safe contract - implemented.

Verification:

- fake tmux sessions can run `--watch --json --count 2 --interval 1` - implemented;
- `jq` can validate two emitted snapshots and the existing row schema - implemented;
- `--count 0` exits without polling - implemented;
- no external credentials, real Claude/Codex calls, GitHub writes, scheduling, or release actions.

## P0: Exit Detail Contract

Extend wrapper `status --json` with minimal exit detail - second slice implemented:

- `exit_code`: integer or null, parsed from wrapper exit-code markers - implemented;
- preserve `running`, `exit_detected`, `blocked_reason`, and `diagnostic` semantics - implemented;
- treat exit details as machine-readable evidence, not root-cause diagnosis - implemented.

Rationale:

- `blocked_reason: cli_exited` currently tells callers that the CLI ended, but not whether it ended cleanly;
- operators need a stable field before deciding whether to restart, inspect, or ignore a session.

Verification:

- fake local and remote exit markers produce expected `exit_code` - implemented;
- missing/running sessions report `exit_code == null` - implemented;
- existing stable status fields keep their names and types - implemented.

Implementation note: the intended source is the existing pane footer markers, such as `local command exited with code <n>` and `remote command exited with code <n>`. Do not infer exit codes from arbitrary model output.

## P1: Transcript Contract Versioning

Add explicit schema-version validation - third slice implemented:

```bash
tmux-agent-dialogue validate-transcript --schema-version 1 --transcript transcript.jsonl
```

Constraints:

- keep the current transcript shape valid as the initial version - implemented;
- treat the current default validator behavior as schema version `1` - implemented;
- reject unsupported schema versions with a clear error - implemented;
- do not silently upgrade or rewrite transcripts - implemented.

Verification:

- current fake dialogue transcripts validate with the default and explicit schema version - implemented;
- unsupported versions fail before reading external systems - implemented.

## P1: Local Blocked Trigger Artifacts - implemented

Allow bounded dialogue runs to write a local trigger file when a participant becomes blocked:

```bash
tmux-agent-dialogue pair-review \
  --on-blocked-trigger blocked.json \
  --transcript review.jsonl
```

Constraints:

- write only local files requested by flags - implemented;
- never auto-accept permission, approval, SSH, or login prompts - implemented;
- no GitHub posting unless the existing explicit comment command is used - implemented.

Verification:

- fake blocked runs write the trigger artifact - implemented;
- non-blocked runs do not write it - implemented;
- trigger JSON includes participant name, `blocked_reason`, and timestamp - implemented.

## Non-Goals

- real Claude/Codex credentials in CI;
- unbounded watch loops or daemon mode;
- fan-out or fan-in multi-agent orchestration;
- hidden prompt acceptance, GitHub posting, merging, scheduling, cleanup, tag creation, or release publishing;
- personal project names, machine names, hostnames, dotfiles, or private workflow shortcuts in public core;
- status fields that claim authoritative root cause beyond bounded pane evidence.
