# v0.6.0 Roadmap

`v0.5.0` finished the planned observability and multi-session composability surface and passed the reviewed Release workflow dry-run. Publishing the `v0.5.0` tag and GitHub Release still requires an explicit operator go/no-go.

`v0.6.0` should improve composability for scripts and agents without adding release side effects, credentials, private shortcuts, or unbounded orchestration. The theme is: stronger local contracts, clearer machine-readable outputs, and CI checks that catch mistakes before release prep.

Status: candidate roadmap only. No `v0.6.0` implementation branch, tag, GitHub Release, or Formula bump exists.

## Objective

Make tmux-agent-tools outputs easier to consume and safer to evolve:

- generated JSON outputs expose stable contract metadata where scripts need it;
- GitHub comment dry-runs and writes can be inspected structurally without scraping prose;
- shell script quality gates catch common mistakes beyond `zsh -n`;
- local presets cover common review/debate loops while staying bounded and credential-free.

## Current State

Implemented on `main`:

- transcript validation can pin schema version `1`;
- `summarize --output-format json` emits structured summary output;
- GitHub comment helpers are dry-run by default and only post or edit with explicit `--post-github-comment`;
- wrapper and session status expose bounded JSON contracts;
- default CI is credential-free and uses fake participants.

Not done:

- JSON summary output does not include a top-level schema version;
- `github-comment` does not have a structured JSON result mode;
- CI does not run shellcheck;
- there is no first-class `debate` preset;
- session inventory does not expose sort or filter flags beyond existing list/watch behavior.

## P0: CI Script Quality Gate

Add a shellcheck-based quality gate for installed scripts.

Shape:

- run shellcheck against supported-shell helper scripts in CI;
- keep a ShellCheck compatibility sentinel for installed zsh scripts so the unsupported-shell boundary is explicit;
- keep the check credential-free and independent of real Claude/Codex sessions;
- handle zsh-specific idioms with narrow, justified disables rather than broad suppression;
- preserve `zsh -n` syntax checks because shellcheck is not a zsh parser.

Verification:

- CI fails when a supported-shell script has an unhandled shellcheck finding;
- CI proves installed zsh scripts hit only the expected ShellCheck unsupported-shell boundary;
- local validation can run the same shellcheck command;
- existing wrapper self-tests still pass.

## P0: Skill Environment Reference Parity

Keep `SKILL.md`, README, and wrapper behavior aligned for public environment variables.

Shape:

- document wrapper environment overrides in the skill entrypoint where agents discover commands;
- include submit delay, status tail bounds, and clipboard controls that are already supported;
- keep private hostnames, dotfiles, and personal workflow defaults out of public docs.

Verification:

- `rg` proves each public `CLAUDE_TMUX_*` and `CODEX_TMUX_*` override documented in README also appears in `SKILL.md`;
- no private hostnames or local-only paths are introduced.

## P1: JSON Summary Contract Metadata

Add top-level schema metadata to `summarize --output-format json`.

Shape:

- include `schema_version: "1"` for JSON summary output;
- keep Markdown output unchanged;
- reject unsupported future schema versions explicitly when a flag is added later.

Verification:

- fake transcript summary validates with `jq '.schema_version == "1"'`;
- existing JSON fields remain present;
- Markdown summary output remains unchanged by default.

## P1: Structured GitHub Comment Result

Add an explicit JSON result mode for `github-comment`.

Shape:

- support a structured result for dry-run, post, and edit paths;
- report status such as `dry_run`, `posted`, or `edited`;
- include the comment URL or ID only when available from `gh`;
- keep GitHub writes behind explicit `--post-github-comment`.

Verification:

- fake `gh` smoke proves dry-run does not call GitHub;
- fake post/edit paths emit valid JSON with status and command shape;
- prose output remains the default for humans.

## P1: Debate Preset

Add a bounded `debate` preset for structured back-and-forth critique.

Shape:

- reuse the existing bounded dialogue runner and transcript validation;
- require finite `--turns`;
- avoid winner selection, hidden arbitration, or unbounded multi-agent fan-out.

Verification:

- fake four-turn debate smoke passes;
- transcript validation passes;
- `jq` proves alternating speakers and preset label.

## P2: Session Inventory Ergonomics

Improve scriptable inventory consumption without adding daemons.

Candidates:

- `tmux-agent-sessions list --sort <field>`;
- `tmux-agent-sessions list --tool <claude|codex|dialogue>`;
- optional `session_start_time` or `session_age_seconds` when tmux exposes stable source data.

Verification:

- fake tmux session inventory can be sorted and filtered with `jq` assertions;
- missing or unsupported tmux metadata returns `null` rather than invented values;
- watch mode remains bounded.

## Non-Goals

- publishing `v0.5.0` or `v0.6.0` tags without explicit operator go/no-go;
- Homebrew Formula bump before the relevant release tag exists;
- real Claude/Codex credentials in default CI;
- unbounded daemon/watch loops;
- fan-out/fan-in orchestration;
- transcript replay or playback;
- private OpenClaw, Mac mini, hostnames, dotfiles, or personal workflow shortcuts.

## First Candidate Slice

Start with the shellcheck CI quality gate because it is small, credential-free, and reduces risk before the next behavior change:

- add the shellcheck CI command;
- fix or narrowly suppress current findings with reasons;
- keep existing `zsh -n`, Formula, skill metadata, and wrapper self-test gates;
- document any shellcheck caveats in the PR validation notes.
