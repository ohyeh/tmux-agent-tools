# v0.2.0 Roadmap

`v0.1.0` made tmux-agent-tools installable and reliable enough for direct Claude/Codex tmux control. `v0.2.0` should build on those primitives without turning the project into personal workflow glue.

## Direction

The next public product layer is bounded orchestration:

```text
wrapper primitives
  -> reliable session control
  -> bounded agent dialogue
  -> transcripted review/debate workflows
```

## P0: Dialogue Runner

Before the dialogue runner, add the small reliability layer it depends on:

- `wait-text --literal` as an ergonomic alias for exact marker waits;
- Claude first-run/permission confirmation diagnostics in `claude-tmux status`;
- no automatic acceptance of Claude confirmation prompts.

Status: marker readiness layer is done. The first dialogue runner MVP is now scoped to local fake participants, bounded turns, cleanup, and JSONL transcript output. Real Codex/Claude dialogue remains manual pre-release hardening.

Add a generic dialogue runner that starts two configured participants, alternates turns, waits for markers, captures responses, and writes a transcript.

Required properties:

- local-only by default;
- bounded by explicit turn count;
- cleanup owned sessions on success and failure;
- no tools or commands forced into agent prompts;
- transcript written to a user-selected path or stdout;
- no GitHub posting or external side effects.

Proposed command shape:

```bash
tmux-agent-dialogue \
  --turns 10 \
  --workdir . \
  --agent-a codex \
  --agent-b claude \
  --prompt-file prompt.md \
  --transcript transcript.jsonl
```

First implementation branch:

```text
feature/dialogue-runner
```

Acceptance criteria:

- can run a bounded local two-party fake dialogue without manual pane interaction;
- supports `--turns`, `--workdir`, `--agent-a`, `--agent-b`, `--prompt-file`, and `--transcript`;
- writes one JSONL object per turn with `turn`, `speaker`, `marker`, `timestamp`, and `text`;
- stops owned tmux sessions on success;
- attempts cleanup and preserves transcript/error context on failure;
- works with fake tmux participants in CI without requiring real Codex or Claude credentials;
- has one passing documented manual smoke path for real Codex/Claude before release.

## P1: Review Preset

Add a thin preset on top of the dialogue runner:

```bash
tmux-agent-dialogue pair-review \
  --workdir . \
  --prompt-file review.md \
  --transcript review.jsonl
```

This should not post comments or merge PRs. It should only produce a transcript and a concise terminal summary.

## P2: Remote And Publishing

After local dialogue is stable:

- allow one participant to use `start-ssh`;
- support transcript summary generation;
- optionally post to GitHub only with an explicit `--post-github-comment` flag.

## Non-Goals

- personal project shortcuts;
- implicit external side effects;
- unbounded autonomous loops;
- default CI runs that require real Codex or Claude credentials.

## Verification Plan

Minimum local checks:

- shell syntax checks for all scripts;
- `doctor` and `self-test`;
- fake tmux participant smoke for transcript writing with `tmux-agent-dialogue --agent-a fake --agent-b fake`;
- one manual real Codex/Claude dialogue run before release.

CI checks should stay credential-free. Real-agent tests are manual release evidence, not required pull-request checks.
